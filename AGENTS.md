# FullTilt project rules

- First public publication must use only the isolated `artifacts/public-source-1.0.0` repository on `main`, with its clean root commit and GitHub noreply identity. The development repository, all previous local branches/tags and `artifacts/pre-privacy-history.bundle` are private backups, never push sources. Never import their refs into the public repository or use mirror/all/tags pushes. Local privacy work uses `codex/privacy-1.0.0`; after launch, normal public clones follow the public main history.

- Current public release is 1.0.0, explicitly requested on 2026-11-01. Use `codex/privacy-1.0.0` for local maintenance and the isolated clean public main for first publication and `Finals/FullTilt-v1.0.0-win-x64` for its package. Reuse one Final folder per version, preserve Profiles, and snapshot a prior package under artifacts before replacing it. Keep development 4.8 and all older releases/branches, including 4.7, fixed. Future versions require an explicit user request. Public versions/tags use matching numeric metadata (`1.0.0` / `v1.0.0`), without the old development-label conversion.
- GitHub target is `adityabhanushali-arch/FullTilt`, public, MIT. Follow `docs/RELEASING.md` when asked to prepare a release. Preparation, builds, commits and local packages are authorized; creating a remote repository, pushing commits/tags or publishing a release requires the user's explicit approval after reviewing the prepared result. Never infer publication approval from a request to prepare a release.

- Display and edit numeric settings as whole numbers throughout the app, including Movement. Round to nearest with halves up; slider values and steps must be whole. Show fractional ratios as whole percentages where needed to preserve fine control. Keep internal motion/ratio precision and legacy settings meanings; opening or refreshing a page must not rewrite existing values.

- Use the accepted full-color FullTilt logo kit as the default for all future versions: shared `Assets/FullTilt-logo.json` outlines, lime (#C8F35B) lettermark, forest (#18251B) wordmark on light and off-white (#FAFBF7) wordmark on dark. Keep the transparent lime lettermark in the executable, window/taskbar and tray icons. Do not revert to old or monochrome logos unless explicitly requested.

- Menu size is global for desktop pie menus across menus and profiles. Keep the in-app pie preview at its fixed reference size, fitting its pane independently of the desktop size setting. Only desktop pies scale with Menu size; preserve centered icons/text. Keybindings and pie edits remain detached drafts until Save changes; Movement applies and saves immediately. Keep independent 100-step per-tab/per-profile session histories, including undoable Discard/reset/defaults, with grouped slider gestures. Before profile changes or closing, resolve drafts with Save/Discard/Cancel. New pie menu creates four empty unassigned segments directly. Keep atomic persistence and retained edits on save failure, with explicit Save changes and Discard controls in Keybindings and Pie Menus.

- Implement the requested scope in the existing code. Preserve user work, settings and unrelated files. Do not restart implementations or add unrelated features, redesigns or research.
- Inspect Git status/history before editing. Continue on the designated feature branch; inspect and preserve an existing branch before creating another. Checkpoint relevant uncommitted work with explicitly reviewed paths and the configured identity. Never invent an identity, discard changes, reset branches or overwrite accepted older-version builds. Preserve current-version package snapshots under artifacts before replacement. Keep previous branches fixed; do not merge unless explicitly requested.
- Use C#/.NET 10, WPF and Windows XInput, targeting Windows x64. Keep nullable enabled and publication untrimmed. Keep deterministic logic in FullTilt.Core and native input behind platform adapters.
- Process input on its worker. Centralize synthetic ownership, sequences and cleanup in ActionCoordinator/KeyboardOwnership. Preserve partial-send ownership for cleanup; release/cancel and lifecycle cleanup must reset neutral gates. Never persist active input state or force foreground focus restoration.
- Keep existing action IDs and settings meanings stable. Add only necessary schema migrations; preserve exact existing-file backups and disable saving if preservation fails. Do not erase valid unrelated configuration when recovering malformed optional data.
- Use isolated settings and fake input/platform adapters for automated checks. Never launch live emulation, change live settings, manipulate real target windows or claim hardware testing from fakes/offscreen renders.
- Use focused tests during development. For a code release, run the full required Release build/test suite once after the final relevant edits with `./scripts/build.ps1`; publish with `./scripts/publish.ps1 -SkipBuild`, then run `./scripts/verify-package.ps1`. Repeat checks only after relevant changes or to resolve uncertainty. Reuse applicable visual inspections.
- Documentation-only changes require no application build, render or publication. Update existing documents rather than creating parallel versions. Separate automated results from user hardware validation and describe limitations accurately.
- Finish implementation tasks with the actual commit hash, branch/Git status, executable path when applicable, validation results and unresolved issues.

Read additional documents only when relevant:

- [docs/PRODUCT.md](docs/PRODUCT.md): agreed behavior and compatibility constraints; read when changing product behavior.
- [docs/STATUS.md](docs/STATUS.md): current release evidence, protected baselines and outstanding work; read when resuming/releasing work or selecting the next task.
- [README.md](README.md): user setup, operation and build commands; read when changing those instructions.
